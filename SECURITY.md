# Security Policy

## Supported Versions

This repository is a profile README and GitHub Pages site — it does not ship
runnable code. As such there are no "supported versions" in the traditional
sense. Security-relevant changes apply to the current `main` branch.

| Branch  | Supported          |
|---------|--------------------|
| `main`  | :white_check_mark: |

## Reporting a Vulnerability

If you discover a security issue affecting this repository or any of the
projects linked from the "Selected Work" table, please report it privately.

**Preferred channel:** GitHub private vulnerability reporting
(Repository → Security → Advisories → "New draft security advisory").

**Email fallback:** [sachncs@gmail.com](mailto:sachncs@gmail.com) (PGP key on request).

Please **do not** file a public issue for security vulnerabilities.

## What to include

- A clear description of the issue and its impact.
- Steps to reproduce or a proof-of-concept.
- Affected commit SHA or release tag, if known.
- Your name / handle for credit, if you would like acknowledgement.

## Response timeline

- Acknowledgement: within 3 working days.
- Triage and initial assessment: within 7 working days.
- Fix or mitigation: best-effort, depending on severity and scope.

Because this repository ships documentation and static site assets only,
most reports will close as informational. For vulnerabilities in linked
projects, please follow the security policy of the affected project.
